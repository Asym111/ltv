# Подключение кассы Lurea к LTV

## 1. Выпуск ключа

Владелец открывает «Аккаунт» в контексте нужного филиала → «API-ключи».
Указывает название подключения и срок действия. Для полного кассового цикла
нужны разрешения «Баланс», «Чтение чеков», «Покупки», «Возвраты».
Возвраты по умолчанию выключены. Ключ привязан к выбранному филиалу, не ко всем
компаниям и не ко всем филиалам сети. Общий бонусный кошелёк внутри сети сохраняется.

Полный ключ показывается один раз. Повторно прочитать его нельзя: сервер хранит
только SHA-256. При утрате выпустите новый ключ и отзовите старый. После отзыва
следующий запрос будет отклонён; уже выполняющийся запрос может завершиться.
Не отправляйте ключ в чат, Google Sheets, браузерный JavaScript или GitHub.
Редакторы Apps Script имеют доступ к Script Properties: ограничьте их список.

## 2. Script Properties

| Свойство | Значение |
|---|---|
| `LTV_BASE_URL` | `https://ltv-bonus.kz` |
| `LTV_API_KEY` | Ключ, выпущенный владельцем именно для этого филиала |

Sagi-токен, пароль от LTV, `SESSION_SECRET`, `ENCRYPTION_KEY`, доступ к базе и
внутренние WhatsApp-ключи не нужны и не должны передаваться кассе.

Разработчики кассы подключают API из своего серверного приложения.
Для проверки выполните `GET /me`: запрос не создаёт покупок и возвращает
название организации/филиала, идентификаторы, разрешения и режим начисления.
Сверьте организацию с Lurea перед первой продажей.

## 3. API v1

Базовый путь: `https://ltv-bonus.kz/api/integration/v1`.
На каждый запрос: `Authorization: Bearer <LTV_API_KEY>` и
`Content-Type: application/json`. Браузерные cookies и CSRF не нужны.
Ключ не даёт доступ к обычным `/api/settings/`, `/api/accounts/` и другим API.

| Метод | Путь | Разрешение |
|---|---|---|
| GET | `/me` | Любой действующий ключ |
| POST | `/balance` | `balance:read` |
| POST | `/transactions` | `transactions:write` |
| GET | `/transactions/{id}` | `transactions:read` |
| GET | `/transactions/by-external/{external_id}` | `transactions:read` |
| POST | `/transactions/{id}/refunds` | `refunds:write` |

Баланс запрашивается POST, чтобы телефон не попадал в URL и журналы адресов:

```json
{"phone":"77001234567","amount":250000}
```

Ответ: `found`, `available`, `pending`, `total`, `max_redeem`,
`redeem_max_percent`, `earning_mode`. Новый клиент возвращает `found=false`
и нулевой баланс; он создастся при первой успешной покупке.

### Покупка

```json
{
  "external_id": "RCP-20261027-001",
  "request_id": "08459faa-8ca1-48cf-af5d-01c9a565d6ab",
  "phone": "77001234567",
  "amount": 250000,
  "redeem_points": 10000,
  "manual_percent": "5",
  "payment_method": "CARD"
}
```

`amount` — сумма после обычных скидок, ДО списания бонусов, в целых тенге.
Не передавайте 240000 в примере выше: это уже сумма после списания, и вычитание
произойдёт дважды. При доступных 10000 бонусов база начисления равна 240000,
начисление — 12000. Сервер проверяет баланс и лимит списания самостоятельно.
`manual_percent` обязателен в ручном режиме (0–100, до двух десятичных знаков).
В автоматическом режиме поле не передаётся. Валидны CASH/CARD/TRANSFER/
OTHER/MIXED. Дата рождения, если передаётся, имеет формат YYYY-MM-DD.
Поля `tenant_id`, `earned_points`, `paid_amount`, `tier` не принимаются.

Ответ содержит `id`, `external_id`, `status`, `amount`, `cash_amount`,
`redeem_points`, `earned_points`, `earning_mode`, `earn_percent`,
`earn_base_amount`, `refunded_amount`, `refundable_amount`,
`refunded_earned_points`, `refunded_redeem_points`, `replayed`.
Сохраните `id` в строке чека как `ltv_transaction_id`.

### Возврат

```json
{
  "external_id": "REF-20261027-001",
  "request_id": "11cb5fe6-f7f8-461b-bc83-979f58d7606b",
  "full_refund": false,
  "amount": 50000,
  "comment": "Частичный возврат"
}
```

Для полного возврата остатка передайте `full_refund=true`, без `amount`.
Сумма возврата выражается на исходной базе ДО списания бонусов. Не смешивайте её
с фактической денежной выплатой. API корректирует лояльность, но не переводит
деньги через банк. Ответ содержит `transaction`, `refund`, `replayed`.
Если бонусы уже потрачены и отменить начисление невозможно, 409 возвращается
без частичных изменений; требуется разбор ответственным сотрудником.

## 4. Повторы и ошибки

Номер чека `external_id` уникален в филиале навсегда. Номер возврата также
уникален в филиале, даже для разных покупок. Разрешены латинские буквы, цифры,
точка, дефис, подчёркивание, двоеточие и слеш; максимум 128 символов.
Повтор с тем же номером и теми же данными не начисляет/не списывает повторно:
вернётся существующая операция с `replayed=true`. Изменённые данные — 409.
`request_id` — обязательный UUID. Создайте его один раз для операции и сохраняйте
для всех повторов. Для следующей операции создайте другой UUID.
Смена ключа не снимает защиту от повторного начисления.

При тайм-ауте не меняйте номер чека/возврата и данные. Повторите исходный запрос.
При неопределённом результате покупки можно запросить чек по `external_id`.
Не пытайтесь отменять запрос только потому, что клиент не получил ответ.

| Код | Действие |
|---|---|
| 401 | Ключ неверный, отозван или истёк: остановить интеграцию, заменить ключ |
| 403 | Недостаточно разрешений либо организация недоступна |
| 404 | Чек отсутствует в доступном филиале |
| 409 | Конфликт чека/возврата либо недостаточный баланс: разобрать причину |
| 422 | Исправить поля, повтор с новым ID не решает ошибку данных |
| 429 | Подождать `Retry-After`, повторить те же данные |
| 5xx/тайм-аут | Ограниченно повторять с теми же идентификаторами |

Лимит: 120 запросов в минуту на ключ, общий для всех процессов сервера.

## 5. Переключение с Sagi

Остановите старые начисления/списания Sagi и связанные триггеры после согласованного
момента перехода. Старые Sagi order_id нельзя отправлять как внутренние LTV id.
Остатки старых бонусов требуют отдельной согласованной миграции; этот API их
автоматически не импортирует и старые Sagi-покупки не воссоздаёт.

Для новых продаж серверная касса вызывает `POST /transactions` один раз после
подтверждения продажи. Сохраните результат в чеке до отметки синхронизации.
При ошибке сохраните состояние ожидания и повторите позже с теми же данными.
Разработчики кассы сохраняют свои проверки прав сотрудников на проведение
продаж и возвратов: API-ключ не заменяет авторизацию сотрудников.
Для подключения достаточно этой документации, базового адреса и отдельного
ключа Lurea. Готовый код кассы от LTV не требуется.
